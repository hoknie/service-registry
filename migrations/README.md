# migrations/

The whole database schema as one ordered timeline, embedded into the binary with `//go:embed`
(`embed.go`) and applied by [golang-migrate](https://github.com/golang-migrate/migrate)
(`internal/postgres`, ARCHITECTURE.md §7, ADR-0031) through `svc-registry db:migrate`
(`just db-migrate`), never on server start. `svc-registry db:rollback [--count N]`
(`just db-rollback [N]`) reverts the newest ones.

- One migration changes one table; every migration is reversible: a pair
  `<YYYYMMDDHHMMSS>_<name>.up.sql` / `<YYYYMMDDHHMMSS>_<name>.down.sql`
  (`just new-migration <name>` creates both). `down` undoes everything `up` did.
- Plain SQL, Postgres only. A file runs as one statement batch (one implicit transaction): a
  failing file changes nothing, but the ledger `schema_migrations` (columns `version`, `dirty`)
  is left dirty and later runs refuse until the schema is repaired by hand.
- Tables `snake_case` plural; primary key `id uuid PRIMARY KEY` without a default (ids are
  UUID v7 generated by the service, ADR-0008); `created_at` / `updated_at` are
  `timestamptz NOT NULL DEFAULT now()`.
- A merged migration is never edited: the ledger records only the version, so an edited file
  would silently differ between databases. Fix forward with a new migration.
- A dev database migrated before ADR-0031 (an older migration ledger, no `schema_migrations`)
  is wiped and migrated again with `just db-reset`.

Tables so far (one migration each): `users`, `sessions`, `groups`, `group_members` (domain
`access`), `nodes`, `role_bindings`, `project_keys` (domain `catalog`; the tree's `parent_id` is
`ON DELETE RESTRICT`, sibling slugs are unique with `NULLS NOT DISTINCT` — Postgres ≥ 15),
`project_events`, `service_deployments`, `service_environments` (domain `ingest`; raw events are
deleted after `INGEST_EVENT_RETENTION_DAYS`, the deployment history keeps `event_id = NULL`).
`personal_access_tokens` (domain `access`, after the ingest tables; only SHA-256 and the display
prefix of a token, `expires_at = NULL` — no expiry).
`forge_connections`, `forge_groups`, `forge_repositories`, `forge_sync_runs` (domain `forge`,
after the tokens; credentials only as AES-GCM ciphertext or an `env:`/`file:` reference) and an
`ALTER` of `nodes.forge` adding `gitea` — one table per migration.
`branches` (domain `catalog`; addressed by project + name, ADR-0036; the migration creates the
default branch of every project with `default_branch`) and an `ALTER` adding
`forge_connections.branch_include`.
`link_kinds` (with the seven initial kinds; names in all four locales, ADR-0038),
`link_templates`, `node_vars`, `link_targets`, `link_checks` (domain `links`, after the branches;
a kind used by a template cannot be deleted — `RESTRICT`; a target's history goes with it).
`environments` (the directory: order and names, no foreign keys to it — ADR-0042; three initial
rows), `clusters`, `cluster_workloads` (domain `deploy`; tokens only as AES-GCM ciphertext or an
`env:`/`file:` reference) and `ALTER`s adding `nodes.cluster_observation`,
`service_deployments.source` and the `cluster` branch source (their rollbacks refuse while rows
from clusters exist).
`user_identities`, `oauth_login_states` (domain `access`, login through OIDC providers — ADR-0043,
ADR-0044) and `ALTER`s making `users.password_hash` nullable and adding `group_members.source`,
`sessions.method` (the rollbacks of the first two refuse while users without a password or
memberships managed by a provider exist).
`knowledge_settings`, `knowledge_blobs`, `knowledge_snapshots`, `knowledge_files` (domain
`knowledge`, project documentation collected through forge — ADR-0046; the blobs carry a generated
`tsvector` with a GIN index, no Postgres extensions).
`knowledge_sources` (domain `knowledge`, the documentation source of a project — a repository on
a forge, a local directory or git repository, ADR-0047).
`knowledge_patterns` (domain `knowledge`, collection settings of any node inherited per field;
moves the patterns out of `knowledge_settings`, ADR-0048).
`knowledge_blobs_morphology` (domain `knowledge`, the full-text index of blobs with Russian and
English stems plus exact forms, ADR-0049; no new table).
`knowledge_embeddings`, `knowledge_index_state` (domain `knowledge`, chunk embeddings cached by
content and model, the indexing job's lease; the `vector` extension when the server has it, ADR-0052).
Enumerations are `text` + `CHECK`, case-insensitive uniqueness is a unique index on
`lower(...)`, foreign keys say `ON DELETE` explicitly, constraints are named (the stores map
them to stable error codes).
